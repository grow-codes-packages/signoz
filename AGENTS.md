# AGENTS.md — Grow Codes SDK for SigNoz (`signoz`)

Instructions for AI coding agents and humans working in this repository. `CLAUDE.md` is a symlink to
this file. Service-specific notes (vendor quirks, API coverage, emulator limits) live in
`docs/compatibility.md`, the README "Function overview" and `skills/signoz-sdk/SKILL.md`.

## What this repository is

One API for SigNoz in five languages, generated from
[sdk-kit](https://github.com/grow-codes-packages/sdk-kit) (version in `.sdk-kit.json`) and
completed with service code. Categories: **logging,tracing**. The contract for every package is the
sdk-kit specification (`SPEC.md` in sdk-kit): names, defaults, error codes, environment variables,
category interfaces and the Docker contract.

service modules — is service code.

## Generated files rule

- A file whose first lines contain `Generated by sdk-kit <version> — do not edit` belongs to sdk-kit.
  **Do not edit it here.** Change sdk-kit (template), release it, then run `sdk-kit sync` in this
  repository. A local edit is detected (`.sdk-kit.json` keeps a SHA-256 per file) and blocks the
  next sync until it is reverted or forced.
- To take over a generated file for good, delete its header line; sync then leaves it alone.
- Never edit `conformance/` or `.sdk-kit.json` by hand.
- `sdk-kit check` (run in CI) verifies that the required files, badges and workflows are present.

## API parity rule

The five packages expose the **same** functions, options, defaults, error codes and behaviour. Any
change to the public API lands in all five languages in the same pull request, with unit tests in
each and an integration call in the Docker suite. Names follow each language's convention:

| | TypeScript | Rust | Go | Python | Java |
| - | - | - | - | - | - |
| Methods | `camelCase` | `snake_case` | `PascalCase`, `ctx` first | `snake_case` | `camelCase` |
| Errors | `SignozError` + subclasses | `Error` enum, `code()` | `*Error`, `errors.Is(err, signoz.ErrNotFound)` | `SignozError` + subclasses | `SignozException` + subclasses |
| Durations | `…Ms` numbers | `Duration` | `time.Duration` | seconds (`…_s`) / `timedelta` | `Duration` |
| Async | `Promise` + `AbortSignal` | `async` + `blocking` feature | sync with `ctx` | sync + `AsyncSignozClient` | sync + `…Async` |

If one language truly cannot support something, document it in `docs/compatibility.md`.

## Tests and coverage

- Unit tests run against local mock HTTP servers; they never need network access or Docker.
- **Coverage gates** (CI-enforced, first-party code only): TypeScript, Python and Java ≥ 90 % lines
  **and** ≥ 90 % branches; Rust ≥ 90 % lines and ≥ 90 % regions; Go ≥ 90 % statements.
- Unit conformance tests are named after the ids in `conformance/core-unit.md`.
- Test fakes for users of the package ship in the testing module (TypeScript
  `@grow-codes/signoz/testing`, Rust feature `testing`, Go `testkit`, Python
  `grow_signoz.testing`, Java `codes.grow.packages.signoz.testing`).

## Docker integration rules

- `docker/compose.yml` runs `signoz/signoz-community:v0.150.0 (+ signoz-otel-collector + ClickHouse)` plus a one-shot `bootstrap` service that writes credentials
  to `/bootstrap/env`. Tests read that file and `GROW_SIGNOZ_URL`.
- Each language has a `test-<lang>` service (profile `<lang>`). Its Dockerfile packs the package and
  installs it into the consumer project in `<lang>/integration/`, which runs the integration tests
  and the conformance runner.
- Always run through `make test-docker`: it uses a unique Compose project per run, publishes no host
  ports and always runs `docker compose down -v`, even on failure or Ctrl-C.
- Every public function is called at least once against the real service with a round-trip
  assertion. Functions the service cannot serve are listed in `docs/compatibility.md` and covered by
  unit tests.

## Release rules

- Releases are made by [release-please](https://github.com/googleapis/release-please) from
  Conventional Commits on `main` (`feat:`, `fix:`, `feat!:`). Never bump versions or edit
  `CHANGELOG.md` by hand. Use the language as the scope when a change touches one package.
- One release pull request covers all five packages. Tags: `typescript-vX.Y.Z`, `rust-vX.Y.Z`,
  `go/vX.Y.Z` (the Go module lives in `go/`, so its tag must be `go/v…` for `go get` to work),
  `python-vX.Y.Z`, `java-vX.Y.Z`.
- The release workflow publishes to npm, crates.io, PyPI and Maven Central; Go is published by its
  tag. Publishing credentials live only in the release environment of the GitHub repository.

## SigNoz specifics

- **Service modules** (service code in every language): config + client, the query client
  (`queryLogs`, `queryTraces`, `getTrace`, `searchTraces`, `listServices`, `listOperations`,
  `getDependencies`, `listLogFields`, `listFieldValues`, `aggregate`, `queryRange`), the log query
  binding (`search`, `tail`, `listStreams`, `listLabels`, `waitForLog`), the OTLP log exporter +
  `logClient`, `initTracing`, `FilterBuilder` and the aggregate builder. File map: TypeScript
  `src/{client,config,http,query,logs,otlp,traces,aggregate,filter,mapping}.ts`; Rust
  `src/{client,config,http,query,query_logs,query_traces,tail,otlp_logs,init_tracing,aggregate,filter,blocking}.rs`;
  Go `{client,config,query,query_logs,query_traces,query_tail,otlp_logs,init_tracing,aggregate,filter}.go`
  (+ `grpcadapter/`, `zapadapter/`); Python `src/grow_signoz/{client,config,filter,aggregate,_api,_query,_logs,_otlp,_traces,_mapping}.py`
  (sync and async share sans-I/O operations); Java `codes.grow.packages.signoz.{SignozClient,SignozConfig,SignozQueryClient,SignozLogExporter,GrpcLogSender,LiveTail,SignozTracing,FilterBuilder,AggregateBuilder,…}`.
- **Two endpoints**: query API `url` (8080) with `SIGNOZ-API-KEY` (service-account key; only
  queries, `ping` and tail need it); OTLP collector `otlpEndpoint` (4318 HTTP / 4317 gRPC) for
  logs and traces, `signoz-ingestion-key` header/metadata for SigNoz Cloud.
- **Binding decisions** (keep all five languages on them; see the coordinator's DECISIONS):
  - `serverVersion()` with an empty version → `UNSUPPORTED` (the community image reports `""`).
  - `listServices` / `listOperations` = v5 scalar `count()` grouped by `service.name` / `name`
    over the window (default last 1 h).
  - `searchTraces` fills `startMicros`/`spanCount` from the waterfall (ms precision, 4 at a time).
  - Log paging uses the SDK keyset cursor in the Go wire format: base64url without padding of
    `{"v":1,"s","e","o","m","x"}`; `"x"` may be `null` or missing.
  - `getTrace` returns `null`/`None`/empty on 404 **and** when the waterfall has no spans; a
    windowed waterfall (`hasMore`) is completed with raw span queries.
  - Any call on a closed client raises `CANCELLED` ("client is closed"), including
    `logClient`/`initTracing`/`tail`.
  - Limit `0`/unset = default (100 raw, 20 trace search); > 10,000 → `VALIDATION`.
  - A log record without a severity → `INFO`.
  - Tracing protocol: without an explicit endpoint the SigNoz `otlpProtocol` is used unless the
    tracing config picks one (Rust/Python/Java: only `grpc` counts as picked).
- **Wire traps**: server `nextCursor` skips rows of the boundary ms; aggregation aliases are not
  echoed (`__result_<i>`, map by index); unknown routes return `200 text/html` → `UNSUPPORTED`;
  log `data.timestamp` is int64 ns > 2^53; waterfall `time_unix` is ms; empty results are
  `rows: null`; `CONTAINS` is a LIKE pattern (escape `%`/`_`); unknown filter fields return no
  rows plus a warning; span link attributes are dropped.
- **Docker**: `docker/compose.service.yml` (owned here) runs ClickHouse `25.12.5`, the SigNoz OTel
  Collector `v0.144.15` (built from the release binary, migrations first) and
  `signoz/signoz-community:v0.150.0`; `bootstrap/` logs in as the root admin, creates the service
  account `grow-sdk-tests` with the `signoz-viewer` role and an API key, and writes
  `/bootstrap/env` (`SIGNOZ_URL`, `SIGNOZ_API_KEY`, `SIGNOZ_OTLP_ENDPOINT`,
  `SIGNOZ_OTLP_GRPC_ENDPOINT`, `SIGNOZ_OTLP_HTTP_ENDPOINT`, org/service-account ids). Healthy after
  ~1 min, < 1 GiB RAM. Bump the image tags together with the stack catalog.
- Unit-test-only cases and server/language differences: `docs/compatibility.md`.

## Rules for agents

- Keep secrets out of code, tests, fixtures, logs and commit messages. Credentials are always wrapped
  in the redacting secret type; error messages pass through redaction.
- Runtime dependencies must use a licence from the allowlist: Apache-2.0, MIT, BSD-2-Clause,
  BSD-3-Clause, ISC, Zlib, Unicode-3.0, Unicode-DFS-2016, 0BSD, CC0-1.0, MPL-2.0. Never GPL, LGPL,
  AGPL, SSPL, BUSL or EPL at runtime.
- Keep dependencies small; prefer the standard library.
- Before you push: `make lint coverage` for every language you touched (or all of them for shared
  changes), and `make test-docker LANGS="<lang>"` when behaviour against the service changed.
- Update the README function overview, `docs/` and the skill file when the public API changes.
